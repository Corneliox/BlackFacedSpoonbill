# Security Policy

## Supported Versions

Security and operational fixes are prioritized for the latest active major and minor releases of the software suite.

| Version | Supported          |
| ------- | ------------------ |
| 4.0.x   | Yes                |
| 3.0.x   | Limited / Critical |
| < 3.0   | No                 |

---

## Reporting a Vulnerability

The project team takes software security and data integrity seriously. If you identify a potential security vulnerability within the desktop application packaging, client-server communication channels, or dependencies:

1. **Do not disclose publicly**: Please refrain from opening public GitHub Issues or discussions regarding potential exploitable vulnerabilities.
2. **Private Notification**: Contact the lead maintainer directly via GitHub private vulnerability reporting or institutional channels listed in `AUTHORS.md`.
3. **Information to Include**:
   - Description of the vulnerability and its potential impact.
   - Operating system and environment details.
   - Minimal reproducible proof of concept or execution steps.

We will acknowledge receipt within 48 hours and work toward remediation before any public advisory is issued.
